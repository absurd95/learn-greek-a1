# Инструкция для ИИ: как развивать этот словарь

Этот файл предназначен для ChatGPT, Codex, Claude и других ИИ-ассистентов, которым поручили сделать собственный языковой тренажёр на основе этого репозитория или обновить существующий словарь.

## Цель проекта

Сохраняйте проект простым статическим PWA без обязательного сервера и сборщика. Он должен:

- работать на GitHub Pages по относительным путям;
- устанавливаться на телефон;
- работать офлайн;
- сохранять прогресс в браузере;
- показывать карточки и тесты;
- озвучивать изучаемый язык;
- позволять быстро открыть общий алфавитный словарь и найти перевод.

Перед изменениями прочитайте `README.md`, `app.js`, `sw.js` и все файлы из `data/`. Не заменяйте архитектуру без необходимости и не удаляйте пользовательские данные.

## Где находятся данные

| Файл | Содержимое |
|---|---|
| `data/words.json` | существительные, прилагательные и предметная лексика |
| `data/verbs.json` | глаголы в словарной форме |
| `data/adverbs.json` | наречия и короткие наречные конструкции |
| `data/phrases.json` | законченные фразы и устойчивые выражения |
| `data/professions.json` | профессии |
| `data/nationalities.json` | национальности и языки |
| `data/months.json` | месяцы |
| `data/weekdays.json` | дни недели |
| `data/conjugations.json` | спряжения глаголов и русские формы для теста |
| `data/collections.json` | подтемы с постоянными ID и родительскими темами |
| `data/id-aliases.json` | соответствие удалённых дублей основным карточкам |
| `data/verb-sets.json` | подборки глаголов по ID общей базы, без копирования карточек |
| `data/situations.json` | занятия по ситуациям со ссылками на существующие ID |

Базовая карточка выглядит так:

```json
{
  "id": "word-stable-unique-id",
  "greek": "το βιβλίο",
  "russian": "книга",
  "topic": "education",
  "partOfSpeech": "noun",
  "collectionIds": ["education-study"],
  "note": "Необязательное пояснение употребления или образования слова.",
  "new": true
}
```

Для всех карточек `words.json` и `professions.json` обязательны `topic` и `partOfSpeech`. Допустимые темы: `food`, `home`, `clothes`, `education`, `work`, `people`, `city`, `transport`, `time`, `nature`, `objects`, `other`; части речи: `noun`, `adjective`, `pronoun`, `numeral`, `other`. Поле `note` необязательно. Оно показывается под переводом и в общем списке, но не используется как правильный ответ теста.

## Как добавлять новую лексику

1. Сначала найдите слово во всех JSON-файлах. Сравнивайте без учёта регистра, лишних пробелов, точки и вопросительного знака.
2. Проверьте не только точное совпадение, но и варианты через `/`, единственное и множественное число, формы мужского и женского рода.
3. Если карточка уже существует, расширьте её перевод, формы или `note`. Не создавайте дубль.
4. Исправляйте орфографию и перевод исходного списка. Не закрепляйте пользовательскую опечатку только потому, что она была передана в задании.
5. Существительные записывайте с артиклем: `ο`, `η`, `το`.
6. Полезные формы можно объединять: `ο μήνας / οι μήνες`, `όλος / όλη / όλο · όλοι / όλες / όλα`.
7. Длинное объяснение помещайте в `note`, а ответ `russian` оставляйте коротким и удобным для теста.
8. Новую партию помечайте `new: true`. Не копируйте карточку ради раздела «Новые».
9. Выберите тему по значению, а не по форме слова. Профессии хранятся в `professions.json`, но включаются в тему `work` динамически — без копирования.

Идентификатор должен быть уникальным и постоянным. Не меняйте ID существующей карточки без серьёзной причины: избранное, ошибки и просмотренные карточки сохраняются именно по ID.

После изменения данных обязательно запустите `python3 scripts/validate_data.py`. Проверка контролирует JSON, уникальность ID, нормализованные дубли, темы, части речи и наличие спряжения у каждого глагола.

## Формы существительных и обучающие игры

У каждого существительного в словах и профессиях обязательно поле `nounForms`. Это массив вариантов одной карточки, например:

```json
"nounForms": [{
  "key": "main",
  "gender": "feminine",
  "singular": "τσάντα",
  "plural": "τσάντες",
  "genitiveSingular": "τσάντας",
  "genitivePlural": "τσαντών"
}]
```

- `key` постоянен в пределах карточки. Не меняйте его при расширении форм: результаты игры привязаны к ID карточки, ключу, числу и виду задания.
- `gender`: `masculine`, `feminine` или `neuter`. Формы записываются без артиклей. Нужна хотя бы одна форма именительного; родительный добавляйте только после проверки.
- Не угадывайте род и множественное по окончанию. Если форма не проверена, не генерируйте её. Слова только множественного числа не получают искусственного единственного.
- Семейства разных родов и варианты написания хранятся в одной карточке несколькими элементами массива. Для общего рода (ο / η υπάλληλος) явно укажите оба рода. Игра исключает неоднозначные поверхности по всей базе, даже когда выбран фильтр темы.
- Родительный склоняется по словарной модели, а не по одному универсальному правилу. Например: μάθημα → μαθήματος → μαθημάτων; μέλος → μέλους → μελών; σελίδα → σελίδων.
- `game-core.js` содержит правила игр без DOM. Не дублируйте словарь в отдельной игровой базе. Игра на ударение использует одну букву, а не автоматически угаданные слоги.
- Удаляйте только U+0301 (знак ударения), сохраняя диерезис: ΐ → ϊ, ΰ → ϋ. Исключайте фразы, односложные формы и слова с несколькими ударениями. Разные подтверждённые ударения одного написания принимаются как варианты.
- До ответа не показывайте артикль, правильное написание, перевод или озвучивание. После первой попытки ответ фиксируется; озвучивание появляется после проверки.
- Каждую новую карточку проверяйте на автоматическое включение в игры. `stressEntries()` подбирает пригодные многосложные греческие формы с одним проверенным ударением из слов, профессий, глаголов и наречий, кроме числительных. `nounEntries()` подбирает только существительные с проверенными `nounForms`; без них артикли и формы не угадывайте и не генерируйте. Не добавляйте специальные копии карточек в игровые списки: игры строятся из общей базы.
- `progress.games.articles` и `progress.games.stress` содержат отдельные метрики форм. Не смешивайте их с `practice`, `learned` и ошибками перевода и не теряйте при сохранении старого прогресса.
- Текущая игра хранится в `greek-a1-active-game` отдельно от текущего теста перевода. Сессия восстановления сверяется с доступными ключами форм; исчезновение форм не удаляет накопленные результаты.
- Проверяйте игры командой `node scripts/test_games.js`, а существующие занятия на -μαι — `node scripts/test_verb_sets.js`.

Нормативная справка по ударению: https://ebooks.edu.gr/ebooks/v/html/8547/2334/Grammatiki-Neas-Ellinikis-Glossas_A-B-G-Gymnasiou_html-apli/index_B_03.html.

## Глаголы и связанные слова

Для каждого нового глагола обязательно:

1. добавить словарную форму в `verbs.json`;
2. добавить таблицу в `conjugations.json`;
3. указать тип спряжения A1, B1, B2, -ομαι или -άμαι либо явно пометить безличное исключение; это модели спряжения, не уровни CEFR;
4. заполнить греческие и русские формы;
5. проверить связанные существительные и добавить отсутствующие в `words.json`.

Примеры семей слов:

- `γράφω → η γραφή / το γράμμα / το μήνυμα`;
- `τραγουδάω → το τραγούδι → ο τραγουδιστής / η τραγουδίστρια`;
- `υπολογίζω → ο υπολογισμός → ο υπολογιστής`;
- `αρχίζω → η αρχή`;
- `ξεκινάω → το ξεκίνημα`;
- `διαβάζω → το διάβασμα`;
- `χρησιμοποιώ → η χρήση`;
- `σταματάω → το σταμάτημα / η στάση`;
- `τελειώνω → το τέλος`.

Не придумывайте неупотребительные формы. Например, погодные `βρέχει` и `χιονίζει` обычно безличные: таблица может содержать только одну безличную форму вместо искусственного «я дождю».

В тесте спряжений греческий вопрос показывается без местоимения. Поддерживаются оба направления и смешанный режим. Русский ответ должен содержать лицо: `я читаю`, `он говорит`, `мы используем`.

## Неоднозначные переводы

Близкие слова нельзя превращать во взаимоисключающие варианты ответа. Например, несколько наречий могут означать «иногда». Логика `translationsOverlap()` в `app.js` исключает отвлекающие ответы, у которых совпадает хотя бы одна часть перевода.

Сохраняйте это правило при изменении теста:

- слово сравнивается со словами;
- глагол — с глаголами;
- наречие — с наречиями;
- фраза — с фразами;
- совпадающие или пересекающиеся переводы не ставятся рядом.

Если два слова близки, уточните значение:

- `ζητάω` — просить или запрашивать;
- `ψάχνω` — искать;
- `ζω` — жить, быть живым;
- `μένω` — проживать, оставаться;
- `μπορώ` — мочь;
- `ξέρω` — знать или уметь благодаря навыку.

Уточнение должно помогать ученику, но не превращаться в ложное жёсткое правило. Например, `πηγαίνω` и `πάω` часто взаимозаменяемы; различие «регулярное движение / разговорная короткая форма» — учебная подсказка, а не абсолютный запрет.

## Подборки, занятия и прогресс

- `topic` оставляйте для совместимости; интерфейс подтем строится по `collectionIds` и `data/collections.json`. Одну карточку можно включить в несколько подборок, но не копировать её.
- В `data/situations.json` перечисляйте существующие ID карточек и подходящие `collectionIds`. Занятие автоматически включает карточки этих тематических подборок плюс вручную выбранные ID. После добавления карточек проверьте, подходят ли они к существующим ситуациям. Слова, глаголы и наречия назначайте подходящим `collectionIds` (для тематического подбора) либо закрепляйте ID вручную. Если подходящей ситуации нет, создайте занятие и назначьте ему подборку и карточки. Следите, чтобы в каждом тестируемом занятии были слова и глаголы; фразы оставляйте материалом для просмотра, не теста. Не копируйте карточки. Смешанный набор включает слова, глаголы, наречия и короткие фразы, но не целые таблицы спряжений.
- Если длинный диалог нужно тестировать по репликам, оставьте исходную карточку как пример, создайте короткие карточки с `sourceId` исходной фразы и постоянными новыми ID.
- При объединении настоящего дубля запишите старый и основной ID в `data/id-aliases.json`. Не объединяйте синонимы и слова с разными значениями. Миграция в `app.js` переносит избранное, ошибки, просмотры и метрики тренировок.
- `learned` в локальном прогрессе означает только «просмотрено». Результаты теста лежат в `practice`: число ответов, правильных, последний ответ и дата. Не называйте просмотренные карточки выученными.
- Раздел «Важные выражения» использует существующие карточки `phrases.json` с `important: true`, не копируя их. Отмечайте короткие частотные фразы, проверяйте пересечения переводов; ID и прогресс остаются общими с разделом «Фразы».
- Ручной выбор карточек в списке задаёт вопросы только по выбранным ID, но варианты ответов берутся из текущего раздела. Сохраняйте `scopeKeys` и `candidateKeys` отдельно в сессии; для старых сессий без `candidateKeys` используйте `scopeKeys`. Поиск не меняет выбор, переход в другой раздел сбрасывает его.
- Режим «Знаю / Не знаю» хранит отдельную текущую сессию в `greek-a1-active-self-quiz`, не перезаписывая обычную. Самооценка учитывается в общей `practice`, помечается `lastSource: self` и может быть исправлена до перехода дальше без повторного увеличения числа ответов. При исправлении старого ответа не перезаписывайте более поздний результат другого занятия. В самооценке не требуются отвлекающие варианты и доступны даже отдельные карточки и фразы занятий. Проверяйте режим командой `node scripts/test_self_quiz.js`.
- Самооценка поддерживает оба направления и смешанный режим; её предпочтение хранится отдельно в `greek-a1-self-quiz-direction`. В русском вопросе греческий ответ и озвучивание доступны только после самооценки; повтор и следующая порция сохраняют направление сессии.
- Числительные находятся в `words.json` с `partOfSpeech: numeral` и `numeralKind: cardinal` или `ordinal`. Они открываются отдельным разделом и не включаются в обычные тесты слов. Включайте их в занятия по ситуации, когда они помогают повторить контекст (например, этаж, адрес, цена или дата). Не смешивайте cardinal и ordinal в вариантах ответа; родовые формы одного числа храните одной карточкой.
- При добавлении слова проверяйте тематическую ситуацию, игры на ударение и артикли. Проверяйте, что в каждом занятии есть вопросы по словам и глаголам, а наречия включаются в соответствующих темах; фразы не попадают в тематический тест. Дополняйте тесты новой карточкой и новым занятием, чтобы проверить подбор по тематической связи.
- Перед публикацией проверяйте обновление PWA и офлайн-загрузку всех дополнительных JSON-файлов; поднимайте версию кеша в `sw.js`.

## Подборки глаголов на -μαι
В `data/verb-sets.json` храните `id`, `title`, `description` и `verbIds` существующих карточек из `verbs.json`. Раздел «Глаголы на -μαι · A2» использует набор `passive-a2`; значения и таблицы собираются из общей базы и сохраняют её ID и прогресс. Новое слово не копируйте ради отдельного раздела.
Проверяйте шесть форм настоящего времени и русские формы, особенно модели -άμαι и нестандартные основы. Пассивная форма не равна пассивному значению: χρειάζομαι, έρχομαι, κοιμάμαι. В добавленных примерах различайте переходные и возвратные пары.
Варианты теста берите только из выбранного набора; спряжения учитывайте по ключу `ID:местоимение`. Добавляйте новые JSON в кеш Service Worker и валидатор.
После изменения наборов или логики теста выполняйте `node scripts/test_verb_sets.js`: проверяются оба режима, направления, сохранение и восстановление сессии, результат и следующая порция без повторов. Список A2 — учебная подборка повседневных глаголов, а не рейтинг частотности. Сверяйте выбор с материалами Центра греческого языка: https://www.greek-language.gr/certification/files/document/rsrh_content/12/A2-BOOK-FINAL.pdf.

Для `Ενοικιάζομαι / νοικιάζομαι` по прямому выбору пользователя сохранены все шесть лиц настоящего времени, включая тренировку первого и второго. Не сокращайте таблицу до третьего лица: в пояснении указано, что в объявлениях обычно используются `νοικιάζεται / νοικιάζονται`, а остальные лица в этом значении редки. Тесты подборки рассчитывают количество по `verbIds`, без фиксированного числа глаголов.

## Общий словарь

Виртуальная категория `dictionary` объединяет только `words` и `verbs`. Она сразу открывается в режиме списка, сортируется по греческому алфавиту и ищет по греческому тексту, русскому переводу, типу и пояснениям.

Не создавайте отдельный дублирующий JSON для общего словаря. Он должен собираться из актуальных `words.json` и `verbs.json` функцией `getDeck()`.

В тематическом тесте ложные варианты должны оставаться в выбранной теме и той же части речи. В режиме «Все темы» темы можно смешивать, но часть речи — нет.

## Грамматика

Грамматика находится в `index.html` как одностраничный быстрый справочник. Новое правило добавляйте только когда оно помогает понять добавленную лексику или исправляет частую ошибку.

Для каждого правила желательно дать:

- короткое объяснение по-русски;
- правильную греческую конструкцию;
- один или несколько примеров с переводом;
- кнопку произношения для полезного примера;
- при необходимости поисковые слова и сравнительную таблицу.

Не копируйте сомнительные формулировки без проверки. Например:

- `πού` сохраняет ударение в прямом и косвенном вопросе: `Πού μένεις;`, `Ξέρω πού μένεις.`;
- `που` без ударения — «который / что»;
- `πώς` — вопросительное «как», `πως` — союз «что»;
- `το μνήμα` — могила, а `το μνημείο` — памятник;
- для времени стандартно `έξι και μισή`; `εξίμισι` чаще обозначает количество «шесть с половиной».

Если добавляется новая самостоятельная тема, обновите число тем в `renderDashboard()` и ссылку в оглавлении грамматики.

## Озвучивание

Озвучивание реализовано через Web Speech API. Сохраняйте:

- `SpeechSynthesisUtterance`;
- язык `el-GR` для греческой версии проекта;
- выбор системного голоса соответствующего языка;
- понятное сообщение, если голос отсутствует.

Не добавляйте аудиофайлы для каждой карточки без отдельного требования: это сильно увеличит PWA.

## Офлайн-режим

`sw.js` использует cache-first. После любого изменения HTML, CSS, JavaScript, словарей, изображений или других кэшируемых файлов увеличьте версию:

```js
const CACHE = "greek-a1-v46";
```

## Обязательные проверки

Перед завершением работы:

1. убедитесь, что все JSON-файлы разбираются;
2. проверьте уникальность ID во всей базе;
3. проверьте отсутствие нормализованных дублей греческого текста внутри каждого раздела;
4. убедитесь, что каждый глагол имеет соответствующее спряжение;
5. выполните синтаксическую проверку `app.js` и `sw.js`;
6. выполните `git diff --check`;
7. запустите проект через локальный HTTP-сервер;
8. откройте его как чистую установку PWA и проверьте счётчики;
9. проверьте поиск по греческому слову и русскому переводу;
10. проверьте консоль браузера на ошибки;
11. убедитесь, что версия Service Worker увеличена.

Не проверяйте PWA простым открытием `index.html`: словари загружаются через `fetch`, поэтому нужен HTTP-сервер.

## Git и безопасность изменений

- Сначала посмотрите `git status` и сохраните чужие незавершённые изменения.
- Не используйте `git reset --hard`, принудительную перезапись или массовое удаление файлов.
- После успешных проверок создайте отдельный локальный коммит с понятным сообщением.
- Не выполняйте `git push`, публикацию или изменение GitHub Pages без прямой просьбы пользователя.

## Если проект адаптируется для другого языка

Можно переиспользовать интерфейс и архитектуру, но необходимо:

1. заменить названия и содержимое JSON-файлов;
2. поменять язык синтеза речи;
3. адаптировать сортировку алфавита в `renderWordList()`;
4. заменить грамматику и изображения;
5. обновить название, описание и язык в `manifest.webmanifest`;
6. заменить иконки и адрес GitHub Pages;
7. очистить или переименовать ключ прогресса в `localStorage`, чтобы данные разных приложений не смешивались;
8. обновить Service Worker и выполнить чистую проверку установки.

Главный принцип: одна карточка — один стабильный источник истины. Общие списки, «Новые», избранное, ошибки и тесты должны строиться из этих данных, а не хранить копии.
