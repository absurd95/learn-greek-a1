# Инструкция для ИИ: как развивать этот словарь

Этот файл предназначен для ChatGPT, Codex, Claude и других ИИ-ассистентов, которым поручили сделать собственный языковой тренажёр на основе этого репозитория или обновить существующий словарь.

## Цель проекта

Сохраняйте проект простым статическим PWA без обязательного сервера и сборщика. Он должен:

- работать на GitHub Pages по относительным путям;
- устанавливаться на телефон;
- работать офлайн;
- сохранять прогресс в браузере;
- показывать карточки и тесты;
- озвучивать изучаемый язык;
- позволять быстро открыть общий алфавитный словарь и найти перевод.

Перед изменениями прочитайте `README.md`, `app.js`, `sw.js` и все файлы из `data/`. Не заменяйте архитектуру без необходимости и не удаляйте пользовательские данные.

## Где находятся данные

| Файл | Содержимое |
|---|---|
| `data/words.json` | существительные, прилагательные и предметная лексика |
| `data/verbs.json` | глаголы в словарной форме |
| `data/adverbs.json` | наречия и короткие наречные конструкции |
| `data/phrases.json` | законченные фразы и устойчивые выражения |
| `data/professions.json` | профессии |
| `data/nationalities.json` | национальности и языки |
| `data/months.json` | месяцы |
| `data/weekdays.json` | дни недели |
| `data/conjugations.json` | спряжения глаголов и русские формы для теста |

Базовая карточка выглядит так:

```json
{
  "id": "word-stable-unique-id",
  "greek": "το βιβλίο",
  "russian": "книга",
  "note": "Необязательное пояснение употребления или образования слова.",
  "new": true
}
```

Поле `note` необязательно. Оно показывается под переводом и в общем списке, но не используется как правильный ответ теста.

## Как добавлять новую лексику

1. Сначала найдите слово во всех JSON-файлах. Сравнивайте без учёта регистра, лишних пробелов, точки и вопросительного знака.
2. Проверьте не только точное совпадение, но и варианты через `/`, единственное и множественное число, формы мужского и женского рода.
3. Если карточка уже существует, расширьте её перевод, формы или `note`. Не создавайте дубль.
4. Исправляйте орфографию и перевод исходного списка. Не закрепляйте пользовательскую опечатку только потому, что она была передана в задании.
5. Существительные записывайте с артиклем: `ο`, `η`, `το`.
6. Полезные формы можно объединять: `ο μήνας / οι μήνες`, `όλος / όλη / όλο · όλοι / όλες / όλα`.
7. Длинное объяснение помещайте в `note`, а ответ `russian` оставляйте коротким и удобным для теста.
8. Новую партию помечайте `new: true`. Не копируйте карточку ради раздела «Новые».

Идентификатор должен быть уникальным и постоянным. Не меняйте ID существующей карточки без серьёзной причины: избранное, ошибки и просмотренные карточки сохраняются именно по ID.

## Глаголы и связанные слова

Для каждого нового глагола обязательно:

1. добавить словарную форму в `verbs.json`;
2. добавить таблицу в `conjugations.json`;
3. указать группу A1, B1 или B2 либо явно пометить безличное исключение;
4. заполнить греческие и русские формы;
5. проверить связанные существительные и добавить отсутствующие в `words.json`.

Примеры семей слов:

- `γράφω → η γραφή / το γράμμα / το μήνυμα`;
- `τραγουδάω → το τραγούδι → ο τραγουδιστής / η τραγουδίστρια`;
- `υπολογίζω → ο υπολογισμός → ο υπολογιστής`;
- `αρχίζω → η αρχή`;
- `ξεκινάω → το ξεκίνημα`;
- `διαβάζω → το διάβασμα`;
- `χρησιμοποιώ → η χρήση`;
- `σταματάω → το σταμάτημα / η στάση`;
- `τελειώνω → το τέλος`.

Не придумывайте неупотребительные формы. Например, погодные `βρέχει` и `χιονίζει` обычно безличные: таблица может содержать только одну безличную форму вместо искусственного «я дождю».

В тесте спряжений греческий вопрос показывается без местоимения. Русский ответ должен содержать лицо: `я читаю`, `он говорит`, `мы используем`.

## Неоднозначные переводы

Близкие слова нельзя превращать во взаимоисключающие варианты ответа. Например, несколько наречий могут означать «иногда». Логика `translationsOverlap()` в `app.js` исключает отвлекающие ответы, у которых совпадает хотя бы одна часть перевода.

Сохраняйте это правило при изменении теста:

- слово сравнивается со словами;
- глагол — с глаголами;
- наречие — с наречиями;
- фраза — с фразами;
- совпадающие или пересекающиеся переводы не ставятся рядом.

Если два слова близки, уточните значение:

- `ζητάω` — просить или запрашивать;
- `ψάχνω` — искать;
- `ζω` — жить, быть живым;
- `μένω` — проживать, оставаться;
- `μπορώ` — мочь;
- `ξέρω` — знать или уметь благодаря навыку.

Уточнение должно помогать ученику, но не превращаться в ложное жёсткое правило. Например, `πηγαίνω` и `πάω` часто взаимозаменяемы; различие «регулярное движение / разговорная короткая форма» — учебная подсказка, а не абсолютный запрет.

## Общий словарь

Виртуальная категория `dictionary` объединяет только `words` и `verbs`. Она сразу открывается в режиме списка, сортируется по греческому алфавиту и ищет по греческому тексту, русскому переводу, типу и пояснениям.

Не создавайте отдельный дублирующий JSON для общего словаря. Он должен собираться из актуальных `words.json` и `verbs.json` функцией `getDeck()`.

## Грамматика

Грамматика находится в `index.html` как одностраничный быстрый справочник. Новое правило добавляйте только когда оно помогает понять добавленную лексику или исправляет частую ошибку.

Для каждого правила желательно дать:

- короткое объяснение по-русски;
- правильную греческую конструкцию;
- один или несколько примеров с переводом;
- кнопку произношения для полезного примера;
- при необходимости поисковые слова и сравнительную таблицу.

Не копируйте сомнительные формулировки без проверки. Например:

- `πού` сохраняет ударение в прямом и косвенном вопросе: `Πού μένεις;`, `Ξέρω πού μένεις.`;
- `που` без ударения — «который / что»;
- `πώς` — вопросительное «как», `πως` — союз «что»;
- `το μνήμα` — могила, а `το μνημείο` — памятник;
- для времени стандартно `έξι και μισή`; `εξίμισι` чаще обозначает количество «шесть с половиной».

Если добавляется новая самостоятельная тема, обновите число тем в `renderDashboard()` и ссылку в оглавлении грамматики.

## Озвучивание

Озвучивание реализовано через Web Speech API. Сохраняйте:

- `SpeechSynthesisUtterance`;
- язык `el-GR` для греческой версии проекта;
- выбор системного голоса соответствующего языка;
- понятное сообщение, если голос отсутствует.

Не добавляйте аудиофайлы для каждой карточки без отдельного требования: это сильно увеличит PWA.

## Офлайн-режим

`sw.js` использует cache-first. После любого изменения HTML, CSS, JavaScript, словарей, изображений или других кэшируемых файлов увеличьте версию:

```js
const CACHE = "greek-a1-v16";
```

Если добавлен новый файл, внесите его в `ASSETS`. Иначе он может не работать офлайн.

## Обязательные проверки

Перед завершением работы:

1. убедитесь, что все JSON-файлы разбираются;
2. проверьте уникальность ID во всей базе;
3. проверьте отсутствие нормализованных дублей греческого текста внутри каждого раздела;
4. убедитесь, что каждый глагол имеет соответствующее спряжение;
5. выполните синтаксическую проверку `app.js` и `sw.js`;
6. выполните `git diff --check`;
7. запустите проект через локальный HTTP-сервер;
8. откройте его как чистую установку PWA и проверьте счётчики;
9. проверьте поиск по греческому слову и русскому переводу;
10. проверьте консоль браузера на ошибки;
11. убедитесь, что версия Service Worker увеличена.

Не проверяйте PWA простым открытием `index.html`: словари загружаются через `fetch`, поэтому нужен HTTP-сервер.

## Git и безопасность изменений

- Сначала посмотрите `git status` и сохраните чужие незавершённые изменения.
- Не используйте `git reset --hard`, принудительную перезапись или массовое удаление файлов.
- После успешных проверок создайте отдельный локальный коммит с понятным сообщением.
- Не выполняйте `git push`, публикацию или изменение GitHub Pages без прямой просьбы пользователя.

## Если проект адаптируется для другого языка

Можно переиспользовать интерфейс и архитектуру, но необходимо:

1. заменить названия и содержимое JSON-файлов;
2. поменять язык синтеза речи;
3. адаптировать сортировку алфавита в `renderWordList()`;
4. заменить грамматику и изображения;
5. обновить название, описание и язык в `manifest.webmanifest`;
6. заменить иконки и адрес GitHub Pages;
7. очистить или переименовать ключ прогресса в `localStorage`, чтобы данные разных приложений не смешивались;
8. обновить Service Worker и выполнить чистую проверку установки.

Главный принцип: одна карточка — один стабильный источник истины. Общие списки, «Новые», избранное, ошибки и тесты должны строиться из этих данных, а не хранить копии.
